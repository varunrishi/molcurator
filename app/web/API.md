# MolCurator API

HTTP API for the MolCurator service: generate molecular analogues from a seed structure and
predict their HOMO–LUMO gap with a pluggable set of engines.

- **Base URL (default):** `http://localhost:8000`
- **Content type:** `application/json`
- **Authentication:** none (intended for local / trusted-network use)
- **CORS:** enabled (configurable via `MOLC_CORS_ORIGINS`), so the frontend may run on a
  different origin and point at the API through its configurable base-URL field.
- **Units:** all energies are electron-volts (eV).
- **Version:** reported by `GET /api/health` (`version` field).

All endpoints are under the `/api` prefix. Interactive documentation generated by FastAPI is
available at `/docs` (Swagger UI) and `/redoc` when the server is running.

---

## Conventions

A **gap result** object is returned by the prediction and generation endpoints:

| Field        | Type            | Description                                        |
|--------------|-----------------|----------------------------------------------------|
| `smiles`     | string          | Canonical SMILES of the molecule                   |
| `status`     | `"ok"`/`"failed"`| Whether the calculation succeeded                 |
| `gap`        | number \| null  | HOMO–LUMO gap (eV); `null` when `status="failed"`  |
| `homo`       | number \| null  | HOMO energy (eV), when available                   |
| `lumo`       | number \| null  | LUMO energy (eV), when available                   |
| `in_domain`  | boolean         | Whether the molecule is within the ML applicability domain |
| `error`      | string \| null  | Reason, when `status="failed"`                     |

Results are returned **one per input, in order**; failed molecules are marked, never dropped.

## `GET /api/health`

Report service status and which engines are installed. Call this first — the frontend uses it
to choose the active engine, populate the model selector, and detect a backend that is down.

**Response `200`**

```json
{
  "status": "ok",
  "version": "0.2.0",
  "predictor": {
    "active": "tblite",
    "available": { "delfta": false, "tblite": true },
    "engines": {
      "delfta": { "available": false, "method": "DelFTa Δ-learning (≈ ωB97X-D/def2-SVP)", "error": "ModuleNotFoundError: ..." },
      "tblite": { "available": true,  "method": "GFN2-xTB via tblite (semi-empirical)", "error": null }
    }
  },
  "generator": "GB-GA (Jensen scheme, built-in operators)",
  "embed": "RDKit ETKDG"
}
```

`predictor.active` is `"delfta"`, `"tblite"`, or `"none"` (no engine installed → the client
falls back to its labelled demo estimator).

## `POST /api/predict`

Predict the HOMO–LUMO gap for one or more molecules.

**Request**

| Field       | Type               | Required | Description                               |
|-------------|--------------------|----------|-------------------------------------------|
| `smiles`    | string[]           | yes      | SMILES strings to score                   |
| `predictor` | string \| null     | no       | `"delfta"`, `"tblite"`, or `null` (auto)  |

```json
{ "smiles": ["c1ccccc1", "c1ccc2ccccc2c1"], "predictor": "tblite" }
```

**Response `200`**

```json
{
  "method": "GFN2-xTB via tblite (semi-empirical)",
  "units": "eV",
  "predictions": [
    { "smiles": "c1ccccc1",      "status": "ok", "gap": 6.98, "homo": -9.71, "lumo": -2.73, "in_domain": true,  "error": null },
    { "smiles": "c1ccc2ccccc2c1","status": "ok", "gap": 5.40, "homo": -9.02, "lumo": -3.62, "in_domain": true,  "error": null }
  ]
}
```

A requested engine that is not installed yields `status="failed"` for every molecule with an
explanatory `error` (the API does not silently switch engines, so numbers are never mislabelled).

**Example**

```bash
curl -s http://localhost:8000/api/predict \
  -H 'Content-Type: application/json' \
  -d '{"smiles":["c1ccccc1"],"predictor":"tblite"}' | python -m json.tool
```

## `POST /api/embed`

Generate a 3D geometry (RDKit ETKDG, MMFF-tidied) for a single molecule.

**Request**

```json
{ "smiles": "c1ccccc1" }
```

**Response `200`**

```json
{ "smiles": "c1ccccc1", "xyz": "12\nc1ccccc1\nC  1.39 0.00 0.00\n...", "error": null }
```

On failure, `xyz` is `null` and `error` describes the problem. The geometry is a quick
conformer for visualisation and as a QM starting point; it is not a final optimised structure.

## `POST /api/generate`

Generate candidate analogues from a seed with GB-GA and screen them by predicted gap against a
target window. This is the main workflow endpoint.

**Request**

| Field                        | Type           | Default   | Description                               |
|------------------------------|----------------|-----------|-------------------------------------------|
| `seed`                       | string         | —         | Seed SMILES                               |
| `target.min`                 | number \| null | —         | Lower bound of the target gap window (eV) |
| `target.max`                 | number \| null | —         | Upper bound of the target gap window (eV) |
| `settings.n_candidates`      | int            | 48        | Candidates per round (1–500)              |
| `settings.rounds`            | int            | 3         | Number of GA generations (1–8)            |
| `settings.mutation_strength` | int            | 2         | Edits per mutation (1–5)                  |
| `settings.generator`         | string         | `"gb_ga"` | Generator backend                         |
| `settings.predictor`         | string \| null | `null`    | `"delfta"`, `"tblite"`, or `null` (auto)  |

```json
{
  "seed": "c1ccc2ccccc2c1",
  "target": { "min": 3.0, "max": 5.0 },
  "settings": { "n_candidates": 32, "rounds": 3, "mutation_strength": 2,
                "generator": "gb_ga", "predictor": "tblite" }
}
```

**Response `200`**

```json
{
  "method": "GFN2-xTB via tblite (semi-empirical)",
  "generator": "GB-GA (Jensen scheme, built-in operators)",
  "note": "GFN2-xTB (tblite) is active — capped this run to 32 candidates x 3 rounds ...",
  "candidates": [
    {
      "id": "r1-c000", "smiles": "...", "parent_smiles": "...", "round": 1,
      "generator": "GB-GA (Jensen scheme, built-in operators)",
      "status": "ok", "gap": 4.21, "homo": -8.4, "lumo": -4.2,
      "uncertainty": null, "in_domain": true,
      "method": "GFN2-xTB via tblite (semi-empirical)", "error": null,
      "xyz": "28\n...\n"
    }
  ]
}
```

- `note` is non-null when the server adjusted the request (e.g. capping work for the slower
  semi-empirical engine). The caps are configurable (`MOLC_XTB_CAP_N`, `MOLC_XTB_CAP_ROUNDS`).
- When GB-GA is unavailable (RDKit missing) `candidates` is empty and `note` explains it; the
  client then runs its own demo generator.
- `uncertainty` is `null` for DelFTa and tblite (no per-molecule σ); it is populated only by
  engines that provide one.

---

## Error model

- Malformed requests return `422` with FastAPI's validation detail.
- Per-molecule failures are **not** HTTP errors: they appear as `status="failed"` entries with
  an `error` message, so a partial batch still returns `200`.
- A `500` indicates an unexpected server fault; the body carries the exception message.

## Engines

| Engine  | `predictor` value | Level of theory                         | Install |
|---------|-------------------|-----------------------------------------|---------|
| DelFTa  | `delfta`          | ML Δ-learning, ≈ ωB97X-D/def2-SVP       | conda + one-time weight download |
| tblite  | `tblite` (alias `xtb`) | GFN2-xTB, semi-empirical QM         | `conda install -c conda-forge tblite-python` |

The two engines are different levels of theory; their gaps for the same molecule will differ.
The `method` field always states which produced a given number.
