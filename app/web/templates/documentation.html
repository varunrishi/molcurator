What a run does

MolCurator searches for molecules whose property lies in a target window, starting from your seed. Each round it:

  1. Plans the round (rules or an LLM) and generates new molecules from the best ones so far (STONED SELFIES).
  2. Runs xTB on a random sample of them (30 MMFF94 conformers, then one GFN2-xTB calculation each).
  3. Trains an ML model once enough xTB values exist, and estimates the rest with it.
  4. Screens candidates against the window plus the margin.
  5. With QM on, sends the closest candidates to QM (ORCA DFT) within the QM budget.
  6. Curates molecules whose best estimate is inside the window, then decides whether to continue.

A run stops at the dataset size, or when rounds, QM calls or time run out. Stopped runs can be resumed.

How far to trust a value

  • QM DFT single point (e.g. B3LYP/def2-SVP). The level the target window is meant for.
  • xTB GFN2-xTB, semi-empirical. Fast but offset from DFT: in the repo's local analysis, B3LYP gaps were on average 2.55 eV higher than xTB gaps (60 molecules).
  • ML Model trained on xTB values. The README reports a test error of about 0.5 eV: a candidate to check, not a result.
