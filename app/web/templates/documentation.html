What a run does

MolCurator searches for molecules whose property lies in a target window, starting from your seed. Each round it:

  1. Plans the round (rules or an LLM) and generates new molecules from the best ones so far (STONED SELFIES).
  2. Predicts the property for a random sample of them: MMFF94 conformers (30 by default), then one calculation on the lowest. GFN2-xTB (tblite, seconds) where xTB can give the property; otherwise B97-3c through ORCA (e.g. TD-DFT for the S1–T1 gap, minutes). For the HOMO–LUMO gap preset, xTB gaps are corrected to DFT-like values with a linear fit.
  3. Trains an ML model once enough PREDICT values exist, and estimates the rest with it.
  4. Screens candidates against the window plus the margin.
  5. With QM on, sends the closest candidates to QM (ORCA DFT) within the QM budget.
  6. Curates molecules whose best estimate is inside the window, then decides whether to continue.

A run stops at the dataset size, or when rounds, QM calls or time run out. Stopped runs can be resumed.

How far to trust a value

  • QM DFT calculation (e.g. B3LYP/def2-SVP) with ORCA. The level the target window is meant for.
  • xTB→DFT GFN2-xTB gap corrected to a DFT-like value (configs/homo_lumo.yaml: fitted on 60 xTB/B3LYP/def2-SVP pairs, typical error 0.455 eV). The molecule's details also show the raw xTB value, and say when it lies outside the fitted range.
  • xTB raw GFN2-xTB value, semi-empirical. Fast; for gaps, well below DFT values unless corrected.
  • B97-3c PREDICT by DFT/TD-DFT through ORCA, for properties xTB cannot give.
  • ML Model trained on PREDICT values. The README reports a test error of about 0.5 eV (HOMO–LUMO gap): a candidate to check, not a result.
